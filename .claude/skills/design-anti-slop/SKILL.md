# design-anti-slop — чистильщик ИИ-слопа в дизайне

То же, что фильтр слопа в текстах, но для интерфейса. Философия та же: слоп это статистически безопасное среднее. Модель выбирает самый частый паттерн из датасета, поэтому результат узнаваем и безлик. Скилл не добавляет вкус — он снимает типовое и держит рамки системы. Вкусовые решения остаются за дизайнером.

## Что скилл делает и чего не делает

Делает: находит задокументированные слоп-теллы по каталогу, чинит их к токенам/системе проекта, отчитывается что и почему поменял, предлагает «одно смелое решение», где дизайн остался стерильным.
Не делает: не придумывает бренд за пользователя, не гарантирует «уникальность», не трогает то, что осознанно задумано (если паттерн подтверждён пользователем как решение — не флажить повторно).

## Режимы

- **`audit`** (дефолт) — прогон по каталогу, отчёт: находка → где → какое правило (T-номер) → предлагаемый фикс → severity (ban / system / flag).
- **`fix`** — после согласования аудита: правки + краткий отчёт до/после. Никогда не начинать с fix без показанного аудита, если пользователь явно не сказал «чини сразу».

## Порядок работы

1. **Контекст системы.** Ищем рамки проекта: `DESIGN.md`, `ds/` (foundation/CONTRACT), токены, шрифтовые пары. Есть — чистим К ним (фиксы обязаны использовать токены проекта). Нет — работаем к нейтральной базе и предлагаем завести мини-`DESIGN.md` (палитра-кап, пара шрифтов, запреты), иначе слоп вернётся при следующей генерации.
2. **Определяем носитель:**
   - **Код/веб** (HTML/CSS/Tailwind/React) — основной путь. Генерация идёт сразу в веб, поэтому и аудит, и фиксы по коду: детерминированные проверки грепом/чтением по селекторам из каталога, правки тем же диффом. Самый надёжный режим.
   - **Скриншот/рендер** — визуальная оценка по каталогу, без автофиксов, только отчёт и рекомендации. Для того, что грепом не ловится: ритм, композиция, площадь акцента.
3. **Аудит по каталогу** — [`references/catalog.md`](references/catalog.md). Идти по правилам сверху вниз (баны → системные → связки → копирайт-проход T21), собирать находки с точным местом (файл:строка / область скрина). Приоритет весов из ресёрча: shadcn-дефолты и цвет выше шрифтов, мем-теллы (bento/glass/aurora) не переоценивать.
4. **Отчёт аудита** пользователю. Ждать подтверждения объёма правок.
5. **Фиксы** — минимальными диффами, к токенам системы. После — короткое до/после: что снято, что осталось на вкусовое решение пользователя.
6. **Финальная строка отчёта всегда честная:** «типовой слоп снят; вкус и смелые решения — за тобой» + 1-2 конкретных предложения, где добавить характер (правило 80/20: 80% проверенного, 20% одно смелое решение на экран).

## Каталог правил

Полный каталог с детекцией и фиксами: [`references/catalog.md`](references/catalog.md). Каталог живой: новые подтверждённые теллы дописываются с очередным T-номером.

## Связь с инструментами

- **Mobbin MCP** (реальные экраны ~621к и флоу ~142к топовых приложений, поиск по фиче: онбординг, пейволл, настройки, чекаут). Скилл чистит слоп, но структурный UX-дженерик (находки T17/T18: шаблонная формула экрана, всё по центру, cards-within-cards) чисткой не лечится — это лечится референсом. Если аудит флажит структуру, в отчёте рекомендовать: подтянуть флоу-паттерн через Mobbin MCP и пересобрать секцию на нём. Референс = опора для паттерна, не копирование чужого экрана.
- **Тексты и микрокопи** — отдельный проход текстовым фильтром слопа (здесь T21 ловит английские баззворды регуляркой, русские обороты чистятся текстом).
- **DESIGN.md / токены проекта** — источник правды для всех фиксов; при отсутствии предлагается завести (см. порядок работы, шаг 1).

## Инварианты

1. Аудит перед фиксом. Молча не переделывать.
2. Фиксы только к системе (токены/DESIGN.md проекта), не к «своему вкусу». Хардкод новых hex запрещён так же, как и слоп.
3. Каждая правка объяснена одной строкой: правило + почему.
4. Не флажить одно и то же повторно после явного «это осознанное решение».
5. Скриншот и рендер — только для аудита, автофиксы не по ним; все правки живут в коде/вебе. Скилл заточен под веб-генерацию, Figma-макеты вне его области.
6. Скилл не заменяет ревью дизайнера. В отчёте это проговаривается.
